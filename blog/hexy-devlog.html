Building a Custom Minimax AI Engine for Mobile: A HEX:RESISTANCE Post-Mortem

When I set out to build HEX:RESISTANCE, I knew the core game loop relied heavily on a challenging, dynamic opponent. Standard state-machine AI wasn't going to cut it for a hex-based strategy game; the state space was too vast, and players would quickly identify deterministic patterns. I needed a robust adversarial search algorithm.

I decided to implement a custom Minimax algorithm equipped with Alpha-Beta pruning. However, deploying computationally expensive search trees on mobile devices presented significant challenges, culminating in severe native system crashes due to memory pressure and main-thread blocking.

The State Space Problem

In a hex-based grid, the branching factor can explode exponentially depending on the board size. A naive implementation of Minimax would attempt to evaluate millions of states per turn. On a mobile processor, this drained the battery rapidly and caused the UI to freeze.

// Example of an unoptimized evaluation function
function evaluateState(boardState) {
    let score = 0;
    for (const hex of boardState.hexes) {
        if (hex.owner === AI_PLAYER) score += hex.value;
        if (hex.owner === HUMAN_PLAYER) score -= hex.value;
    }
    return score;
}

While this naive approach works in theory, applying it at depth 6 or 7 on a mobile device immediately caused a timeout. The first optimization was introducing Iterative Deepening alongside Alpha-Beta pruning, ensuring we always had a "good enough" move ready if our allowed time budget ran out before the search concluded.

Solving Native System Crashes

The most critical issue arose during late-game scenarios. The garbage collector simply couldn't keep up with the allocation of new board state objects during the deep recursive search. This excessive object creation led to Out-Of-Memory (OOM) native crashes.

The solution was to eliminate object allocation during the search entirely. I refactored the engine to use a single, pre-allocated flat array representing the board. Instead of cloning the board for each potential move, the engine now applied and reverted moves in-place (a standard technique in modern chess engines).

Conclusion

By heavily optimizing the state representation and moving the intense computation off the main thread via Web Workers, the AI engine now evaluates states efficiently without dropping frames. Building the engine from scratch provided a deep understanding of resource management and adversarial search algorithms on constrained hardware.

HEX:RESISTANCE is now live, and the AI opponent provides a fluid, challenging experience for players.
